# AGENTS.md

This file provides guidance to AI coding assistants when working with code in this repository.

## Project

A Raycast extension that surfaces [mise](https://mise.jdx.dev/) toolchain information (tools, settings, details) inside Raycast. TypeScript + React, targets macOS and Windows.

## Commands

- `npm run dev` — `ray develop`: start Raycast in dev mode with hot reload.
- `npm run build` — `ray build`: production build.
- `npm run lint` / `npm run fix-lint` — Raycast ESLint config.
- `npm run publish` — publish to the Raycast Store (not npm; `prepublishOnly` is wired to block accidental `npm publish`).

Use `npm` (not `bun`) — the lockfile is `package-lock.json` and Raycast's CLI assumes npm.

## Architecture

- `package.json` is the **source of truth** for the extension surface: every entry in the top-level `commands` array maps 1:1 to a file in `src/<command-name>.tsx` whose default export is the command's React component. Adding a command means editing both.
- `preferences` declared in `package.json` (e.g. `misePath`) are read with `getPreferenceValues<Preferences>()` in `src/lib/mise.ts`, typed by the ambient `Preferences` types Raycast generates into `raycast-env.d.ts`. **Do not edit `raycast-env.d.ts` by hand** — it is regenerated by `ray develop` / `ray build` from `package.json`.
- New preferences flow: add to `package.json` → run dev/build to regenerate `raycast-env.d.ts` → read via `getPreferenceValues`.
- `src/lib/mise.ts` resolves the mise binary (preference first, then known install paths) and runs it with `execFile` (no shell). Commands run outside any project folder, so they reflect global/default config only.
- `src/lib/empty-view.tsx` renders the shared mise-not-found / command-failed / empty states for list commands.
- Commands: `mise-list-all-tools` (list, per-tool detail via `Action.Push`, uninstall), `mise-show-settings`, `mise-doctor`, `mise-show-env-vars`.

## Conventions

- Prettier: `printWidth: 120`, double quotes (`singleQuote: false`).
- ESLint: extends `@raycast/eslint-config` — don't add custom rules without reason.
- TypeScript `strict` is on; commands use `react-jsx` runtime, so no explicit `React` import is needed.
